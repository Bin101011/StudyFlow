# StudyFlow 시험

기능을 고친 뒤 **예전 기능이 망가지지 않았는지** 확인하는 자동 시험입니다. 전부 **가짜 Google**과 **임시 DB**로 돌아가서, 진짜 Google 계정과 내 `studyflow.db`, `settings.json`은 건드리지 않습니다.

모든 명령은 **프로젝트 폴더**(StudyFlow)에서 실행합니다.

## 1. 서버 시험 (빠름, 1분 안쪽)

```
.venv\Scripts\python.exe tests\run_tests.py            # 전부
.venv\Scripts\python.exe tests\run_tests.py inbox      # 이름에 inbox가 든 것만
```

파일마다 `PASS 개수 / FAIL 개수`를 한 줄로 보여주고, 하나라도 실패하면 종료 번호가 1입니다. 실패한 검사의 이름도 함께 나옵니다.

| 파일 | 확인하는 것 |
|---|---|
| `test_*_api.py` | 할 일, 프로젝트, 폴더, D-day, 시간표 블록, 메모, 순서 바꾸기, 우선순위, 캘린더 관리 등의 API |
| `test_sync.py` | 일정 기억(캐시)과 변경 확인(syncToken) 동기화 |
| `test_create_event_cache.py` | 일정을 추가·수정·끌어 옮기기·다른 캘린더로 옮기기·삭제한 뒤 다시 불러올 때 Google에 다시 묻지 않고 바로 맞는 내용이 보이는지(Google이 돌려준 결과를 기억에 바로 반영). 그때 틀린 내용이 남지 않는지: 폰에서 같이 바뀐 것, 받아 둔 적 없는 달, 쓰기 전에 시작한 받기가 늦게 끝남, 내가 쓴 일정을 나중에 폰에서 고침, 변경 확인 두 개가 동시에 돎, 보내는 중인 일정을 앞 확인이 먼저 봄(연달아 붙여넣기). 몇 가지는 가짜 Google의 대답을 일부러 붙잡아 두어 순서를 맞춘다 |
| `test_connection.py` | 끊긴 연결을 새 연결로 다시 시도하는 부분 (로컬 가짜 서버로 재현) |
| `test_db_indexes_backup.py` | DB 인덱스(할 일 9,000개에서의 속도)와 하루 한 번 DB 백업 |
| `test_single_instance.py` | StudyFlow를 두 번 켜지 못하게 하는 잠금 (프로세스를 실제로 여러 개 띄운다). 창을 닫자마자 다시 켜면(앞 프로그램이 아직 끝나는 중) 거절하지 않고 기다렸다가 켜지는지, 진짜로 켜져 있으면 약 5초 뒤 거절하는지. 창 안 브라우저의 작업 폴더를 실행마다 새로 정하고, 남은 옛 폴더는 기다리지 않고 지울 수 있는 것만 지우는지(이름이 다른 폴더는 안 지움) |
| `test_quick_exit.py` | 창을 닫으면 프로그램이 바로 끝나는지: 뒤쪽 작업자(동기화 확인·미리 받기)나 일정 작업자가 오래 걸리는 일을 하는 중이어도 기다리지 않고 끝나는지, 화면 요청이 결과를 기다리는 일(Google 쓰기 등)은 끝까지 처리되는지. 파이썬 종료 뒤처리가 느려도(.NET 종료 흉내) 바로 끝나는지, 그 전에 화면 요청 스레드의 저장은 기다리는지 (프로세스를 실제로 띄워 잰다) |
| `test_credentials_missing.py` | `credentials.json`이 없거나 깨졌을 때, "인터넷 연결을 확인하세요" 대신 그 파일 안내가 나오는지. 다른 오류는 예전처럼 인터넷 안내인지. 정상 파일은 로그인 단계로 가는지(브라우저는 열지 않는다) |
| `test_login_timeout.py` | 로그인 창을 끝내지 않고 닫았을 때 영원히 기다리지 않는지: 제한 시간 뒤 "로그인이 끝나지 않았습니다" 안내, 그동안 DB·설정 요청은 바로 처리, 그 뒤로는 로그인 탭을 저절로 다시 열지 않고 새로고침 버튼을 누를 때만 다시 여는지. Google 로그인 화면에서 "취소"를 누른 경우도 같은지(진짜 로그인 대기를 쓰고 브라우저는 여는 척만 한다) |
| `test_settings_api.py` | 설정 저장이 원래 설정을 덮어쓰지 않는지: 일부 값만 보내면 그 값만 바뀌고 vault 경로·숨긴 캘린더·만든 캘린더 등은 그대로인지, 객체가 아닌 값은 400인지, settings.json을 못 읽으면(잠김) 기본값 대신 503을 주고 저장도 거부하는지, 깨진 파일은 `settings.broken-…json`으로 남기고 한 번 알리는지, 캘린더를 만들면 서버가 "StudyFlow가 만든 캘린더"로 기록하는지 |
| `test_login_expired.py` | 켜 둔 앱에서 로그인이 만료됐을 때(테스트 상태 앱은 7일마다) "오프라인·인터넷 확인" 대신 "로그인 필요"로 알리는지, 로그인 창을 저절로 열지 않는지, 새로고침으로 다시 로그인하면 껐다 켜지 않아도 정상으로 돌아오는지. 동기화 상태의 "로그인 기다리는 중/로그인 필요", 인터넷 문제가 아닌 오류가 로그에 남는지, 1분 반복이 오류 한 번에 멈추지 않는지. Google 대신 이 컴퓨터 안(127.0.0.1)의 작은 가짜 서버가 대답하고, 밖으로 나가려는 요청은 막고 실패로 기록한다 |

`fake_google.py`가 가짜 Google입니다. 시험이 `app`을 가져오기 전에 DB와 설정 파일의 위치를 임시 폴더로 바꿔 둡니다. **새 시험 파일을 만들 때도 `import fake_google`을 `import app`보다 먼저 하세요.** 안 그러면 진짜 DB에 씁니다.

## 2. 화면 시험 (느림, 파일마다 1~3분)

실제 화면에서 마우스를 끌고 키보드를 치는 시험입니다. 눈에 안 보이는 Microsoft Edge를 직접 띄워서 조종합니다(CDP).

필요한 것: **Node.js**(`node --version`이 나오면 됩니다)와 Edge(`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`).

```
.venv\Scripts\python.exe tests\browser\run_browser_test.py steps     # steps_test.mjs 하나
.venv\Scripts\python.exe tests\browser\run_browser_test.py all       # 전부 차례로 (10분쯤)
```

실행기가 시험마다 시험 서버(5057번 포트)를 새로 띄우고, 끝나면 끕니다. 이전 시험이 남긴 계획/메모가 있으면 엉뚱하게 실패하기 때문입니다.

### 응답 늦추기·실패 스위치 (`memo_server.py`)

화면 시험이 "서버나 Google이 느릴 때", "저장에 실패할 때"를 만들 때 쓴다. 시험 안에서 이 주소를 부르면 그 뒤로 맞는 요청이 늦어지거나 실패한다.

```
/__test/rule?method=POST&path=/api/events&ms=2000&count=1             다음 일정 저장 한 번을 2초 늦춘다
/__test/rule?method=POST&path=/api/events&ms=500&status=502&count=1   0.5초 뒤 502로 실패시킨다(저장하지 않음)
/__test/rule?method=GET&path=/api/time-blocks&ms=2000,0&count=2&after=1   처리한 뒤 응답만 늦춘다(옛 내용이 늦게 도착), 두 번째는 바로
/__test/rule                                                           모든 스위치를 끈다
```

`ms`를 여러 개 주면 맞는 요청마다 차례로 쓴다. `count`가 없으면 끌 때까지 계속 적용된다.

### 알려진 함정

- **같은 5057번 포트를 쓰는 시험을 동시에 돌리지 마세요.** 서로의 서버를 죽입니다.
- **마우스를 움직일 때마다 정확히 5초씩 걸리고 전체가 몇 배로 느리면**, 시험용 Edge 페이지가 "숨김" 상태(`document.visibilityState === "hidden"`)라서입니다. 앱 버그가 아닙니다. 시험 파일 머리말이 Edge를 띄울 때 `--disable-renderer-backgrounding` 등의 옵션을 주고 `Page.setWebLifecycleState`로 깨워서 해결해 두었으니, 새 화면 시험을 만들 때는 기존 시험의 머리말(1~16줄)을 그대로 쓰세요.
- 시험용 Edge는 `%TEMP%`에 `edge_t_`로 시작하는 프로필 폴더를 만드는데, 한 개가 약 300MB입니다. **실행기(`run_browser_test.py`)가 시험마다 그 시험이 새로 만든 폴더를 지웁니다.** 시험이 오류로 죽어서 Edge가 남아 있어도 실행기가 그 Edge(이름에 `edge_t_xxxxxx`가 든 것만. 내가 쓰는 Edge는 건드리지 않습니다)를 끄고 지웁니다. 예전에는 안 지워서 112개, 약 32GB가 쌓였습니다. 단, 실행기 없이 `node tests\browser\xxx_test.mjs`를 직접 돌리면 폴더가 남으니, 그때는 `%TEMP%`의 `edge_t_*` 폴더를 직접 지우세요.
- 마우스로 누를 줄은 **화면 안으로 스크롤한 뒤에** 위치를 재야 합니다. 프로젝트 카드는 마우스를 올리면 `[+ 메모]` 버튼 때문에 내용이 35px 내려오니, 먼저 마우스를 올려 둔 뒤에 재세요. 시간표를 스크롤하면 작은 창이 닫히므로 스크롤 직후 150ms 기다립니다.
- 이 PC의 Edge에는 광고 차단 확장 프로그램이 있어서 `Could not establish connection. Receiving end does not exist` 오류가 자바스크립트 오류 목록에 섞입니다. 시험이 이미 걸러냅니다.
- `tl_test`의 몇 검사(`포인터가 가리킨 시각이 제자리에 남는다`, `빈 제목으로 벗어나면…`)와 `test_sync.py`의 1건은 타이밍 때문에 가끔 흔들립니다. 한 번 더 돌려서 통과하면 문제가 아닙니다. (`화면에 점선 계획 블록이 보인다`, `두 번째 클릭에 지워진다`는 시험이 화면을 너무 일찍 봐서 흔들렸던 것이라, 2026-11-03에 기다린 뒤 보게 고쳤습니다)
- 서버 시험은 시스템 파이썬이 아니라 `.venv\Scripts\python.exe`로 돌려야 합니다(라이브러리가 거기에 설치돼 있습니다).
