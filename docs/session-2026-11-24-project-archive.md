## 1. 시작: "보관 기능은 있는 게 나을까?"

사용자의 질문: 프로젝트 탭의 끝난 프로젝트는 지금 다 삭제하고 있고, D-day도 사실상 그렇다. 보관 기능이 있는 게 나을까?

코드를 확인해서 **지울 때 실제로 무엇이 없어지는지**를 보고 판단했다.

| | 지우면 일어나는 일 | 결론 |
|---|---|---|
| **D-day** | D-day 한 줄만 지워진다. 다른 데이터와 연결이 없다 | 보관 기능 **안 만듦** |
| **프로젝트** | ① 날짜 없는 단계는 함께 지워진다 ② 날짜 있는 할 일은 남지만 **프로젝트 연결이 끊겨서**, 지난 날짜를 다시 볼 때 프로젝트 이름표와 색이 사라진다 | 보관 기능 **만듦** |

갈림길이 된 질문은 "지난 날짜를 다시 열어 무슨 프로젝트를 했는지 볼 일이 있나?"였다. 사용자가 "있을 것 같다"고 해서 만들기로 했고, 바로 시작했다.

## 2. 만든 것

### 쓰는 방법
1. 프로젝트 카드의 **[수정]** → 창 아래쪽 **[보관]** (삭제 버튼 옆)
2. 안 끝낸 단계가 있으면 버튼이 "안 끝낸 단계 N개 · 그래도 보관?"으로 바뀌고, **한 번 더 눌러야** 보관된다
3. 카드가 목록 맨 아래 **"▸ 끝난 프로젝트 N개"** 구역으로 옮겨진다 (처음엔 접혀 있고, 누르면 펼쳐진다)
4. 되돌리려면 그 카드의 [수정] → **[보관 풀기]** → 원래 폴더로 돌아간다

### 보관하면 달라지는 것
- **그대로 남는 것:** 지난 할 일의 프로젝트 이름표와 색, 단계, 들어 있던 폴더 정보
- **빠지는 곳:** 폴더 요약(개수·평균·임박), 오늘 탭의 프로젝트 고르는 칸, 우선순위 탭(남은 단계)
- **카드 모양:** 조금 흐림(마우스를 올리면 또렷), 마감일이 지나도 빨간 강조 없음, 폴더로 끌 수 없음
- 보관한 채로 삭제도 할 수 있다

### 일부러 하지 않은 것
- **Ctrl+Z로 보관 되돌리기:** Ctrl+Z는 오늘 탭 전용이고, [보관 풀기]로 바로 되돌릴 수 있어서
- **접힘 상태 저장:** 가끔 지난 프로젝트를 찾아볼 때만 펴는 곳이라 앱을 켤 때마다 접힌 채로 시작한다
- **D-day 보관:** 위 표의 이유

## 4. 새로 나온 개념

- **`ALTER TABLE ... ADD COLUMN`**: 이미 있는 DB 표에 칸을 하나 덧붙이는 SQL 명령. 앱을 켤 때 `init_db`가 `archived` 칸이 없으면 만들고, 기존 프로젝트는 모두 0(보관 안 함)으로 시작한다. 하루 한 번 하는 DB 백업이 이 작업보다 먼저 실행된다.
- **`COALESCE(값, 대신 쓸 값)`**: 앞의 값이 비어 있으면(NULL) 뒤의 값을 쓴다. 프로젝트가 없는 할 일은 `p.archived`가 비어 있어서 `COALESCE(p.archived, 0)`으로 0으로 보게 했다. 그래야 프로젝트 없는 할 일이 우선순위 탭에서 같이 빠지지 않는다.
- **CSS `column-span: all`**: 여러 열로 나눈 상자 안에서 그 요소만 모든 열을 가로지르게 한다. 폴더 2열 배치에서도 "끝난 프로젝트" 구역이 맨 아래 전체 폭을 쓴다.
- **`insertBefore(새 요소, 기준 요소)`**: 기준 요소 바로 앞에 끼워 넣는다. 기준이 `null`이면 맨 끝에 붙인다.

## 5. 시험

- **서버 시험:** 전체 915건 통과 (새 파일 24건 포함). 옛 DB에 칸이 덧붙는지, 보관·풀기, 지난 할 일 이름표 유지, 우선순위 탭에서 빠지고 돌아오는지, 틀린 값 5가지가 400인지 등.
- **화면 시험:** `archive_test` 통과(세 번 연속), 프로젝트 탭을 쓰는 기존 `steps_test`, `pmemo_test`도 통과.

### 화면 시험을 만들며 고친 점 (앱 문제가 아니라 시험 쪽 문제)
1. **시험 서버의 데이터를 잘못 가정함:** "폴더 없음" 프로젝트가 하나뿐인 줄 알았는데 세 개였다. 시험 순서를 고쳤다.
2. **엉뚱한 곳이 눌림:** 카드에 마우스가 올라가면 [+ 메모] 버튼이 나타나 카드 높이가 바뀐다. 시험이 위치를 먼저 재고 마우스를 옮기면, 그 사이 아래 카드가 밀려서 다른 곳을 눌렀다. → 사람처럼 **마우스를 먼저 올리고, 위치를 다시 잰 뒤 누르게** 고쳤다.
3. **검사가 너무 빨랐음:** 화면이 다시 그려지기 전에 검사해서 한 번 실패했다. → 고정된 0.7초 대신 최대 3초까지 기다리게 고쳤다.

## 6. "지난 날짜 할 일에서 이름표가 사라지는 것 같다" 확인

사용자가 앱에서 써 보고 지난 날짜에서 이름표가 사라지는 것 같다고 했다. DB를 **읽기만** 하고(원본은 건드리지 않음) 확인한 결과, 보관 기능의 문제는 아니었다.

- 보관한 "Micro 발표"의 할 일("log #2" 11/02, "ppt 완성" 11/08)은 이름표가 그대로 나온다. DB 복사본으로 화면을 띄워 사진으로도 확인했다.
- 11/01~02의 "Micro Project log 작성 후 제출", "중국어 문화 ppt 만들기" 같은 할 일은 **처음부터 프로젝트에 연결되지 않았다.** 남아 있는 백업 14개(11/11~11/24)에서도 한 번도 연결된 적이 없다.
- 예전에 지운 프로젝트(1, 4, 5, 6, 15번)는 11/11 전에 지워져서, 그 할 일들의 연결은 백업으로도 되살릴 수 없다. 앞으로 보관을 쓰면 이런 일이 생기지 않는다.
- 참고: 캘린더 탭은 **날짜를 정해 둔** 할 일만 센다. 날짜 없이 체크만 한 프로젝트 단계는 보관과 관계없이 원래 캘린더 탭에 나오지 않는다.

사용자가 확인하고 문제없다고 했다.
